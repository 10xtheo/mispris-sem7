## Обоснованные проектные решения

1. **Python вместо дополнительных SQL-процедур №7.** Сохранено пожелание пользователя и архитектура слоёв. Имена процедур преподавателя сопоставлены методам и описаниям API. SQL-функции готовой №6 сохранены.
2. **Вариант — обычное изделие с расширением.** Общая таблица item сохраняет совместимость со справочником, единицами и технологией. Роль и template_id отделены от модификаций BOM №5.
Функции, классы функций, операторы, формальные аргументы, константы, вызовы, фактические аргументы и корни ограничений хранятся в связанных таблицах миграции 005. JSON используется для передачи запросов; поля definition/expression с хранимыми деревьями удалены. Интерпретатор читает нормализованные записи.
4. **Печать заказа — HTML и сохранение PDF браузером.** Страница содержит наименования, параметры, расшифровки перечислений и единицы. JSON остаётся машиночитаемым представлением документа.
5. **Себестоимость — по конкретной технологии.** Для демонстрационных вариантов применён типовой процесс с собственными нормами. Без маршрута варианта программа возвращает 409. Каждая позиция — отдельная партия, без объединения подготовительного времени между позициями.
6. **Каркас без визуального конструктора правил.** Библиотека функций задаётся через Swagger структурированными запросами; произвольный Python-код не исполняется. Редактор деревьев не был обязательным требованием каркаса.

## Читаемость

Десять схем разделяют настройку, заказы, классы и четыре фрагмента хранения. Базовый текст схем имеет размер 24 px в координатной системе около 900 px; при размещении на ширину 16,5 см это примерно 12,5 пт. PNG имеет тройное разрешение; исходники drawio остаются редактируемыми. Поля таблиц и подписи связей не требуют увеличения страницы для чтения.
